# eHal Camera SDK V1 开发环境搭建说明

本文档用于客户在 Ubuntu 或 Windows WSL2 Ubuntu 中搭建 eHal Camera SDK V1 应用开发环境。工具链文件已经随本文档目录离线提供，安装过程不需要联网下载交叉编译工具链。

## 1. 本目录内容

```text
docs/开发环境/
├── 开发环境搭建说明.md
├── scripts/
│   ├── setup_dev_env.sh
│   └── toolchain_env.sh
├── cmake/
│   └── arm-linux-musleabi-toolchain.cmake
├── runtime/
│   ├── include/openssl/
│   └── lib/libcrypto.so*
└── toolchain/
    └── packages/
        ├── workcard-arm-linux-musleabi-toolchain-20250305.tar.gz
        └── workcard-arm-linux-musleabi-toolchain-20250305.tar.gz.sha256
```

各文件用途：

| 路径 | 用途 |
| ---- | ---- |
| `scripts/setup_dev_env.sh` | 校验并安装随 SDK 提供的固定 ARM musl 工具链 |
| `scripts/toolchain_env.sh` | 固定工具链版本、归档名称和默认安装路径 |
| `cmake/arm-linux-musleabi-toolchain.cmake` | CMake 交叉编译工具链文件 |
| `runtime/include/openssl/` | `camera_web_demo` 使用的 OpenSSL 头文件 |
| `runtime/lib/libcrypto.so*` | `camera_web_demo` 链接和板端运行使用的 OpenSSL crypto 库 |
| `runtime/lib/libssl.so*` | HTTPS/TLS 场景预留的 OpenSSL ssl 库 |
| `toolchain/packages/*.tar.gz` | 固定版本离线交叉编译工具链 |
| `toolchain/packages/*.sha256` | 工具链归档 SHA-256 校验文件 |

## 2. 支持的开发机

客户开发机使用以下环境：

- Ubuntu 22.04/24.04 x86_64。
- Windows 11 + WSL2 Ubuntu 22.04/24.04。

SDK 的 Linux 脚本只在 Ubuntu Bash 或 WSL2 Ubuntu Bash 中执行。Windows PowerShell、CMD、MinGW、Cygwin 不用于执行 `.sh` 脚本，也不用于运行 ARM 交叉编译器。

## 3. Ubuntu 基础命令

Ubuntu 或 WSL2 Ubuntu 需要具备以下命令：

- `bash`
- `tar`
- `gzip`
- `sha256sum`
- `file`
- `readelf`
- `cmake` 3.14 及以上

缺少基础命令时，在 Ubuntu 中执行：

```bash
sudo apt-get update
sudo apt-get install -y bash tar gzip coreutils file binutils cmake
```

以上软件包只提供基础命令，不提供本项目交叉编译工具链。本项目交叉编译工具链固定使用 `docs/开发环境/toolchain/packages/` 中随 SDK 提供的离线包。

## 4. Windows WSL2 进入方法

在 Windows PowerShell 中只执行：

```powershell
wsl
```

进入 WSL 后，提示符从 `PS C:\...>` 变为类似 `user@host:~$`。从该提示符开始执行 Linux 命令。

Windows 路径 `D:\客户目录\work_card_SDK_V1` 在 WSL 中对应：

```text
/mnt/d/客户目录/work_card_SDK_V1
```

进入 SDK 根目录示例：

```bash
cd /mnt/d/客户目录/work_card_SDK_V1
```

## 5. 安装固定工具链

在 Ubuntu 或 WSL2 Ubuntu Bash 中，进入 SDK 根目录后执行：

```bash
cd docs/开发环境
./scripts/setup_dev_env.sh
```

安装脚本执行以下固定流程：

1. 读取 `scripts/toolchain_env.sh` 中的固定工具链名称。
2. 检查 `toolchain/packages/workcard-arm-linux-musleabi-toolchain-20250305.tar.gz` 是否存在。
3. 使用 `toolchain/packages/workcard-arm-linux-musleabi-toolchain-20250305.tar.gz.sha256` 执行 SHA-256 校验。
4. 将工具链安装到当前 Linux 用户目录。
5. 校验 `arm-linux-musleabi-gcc` 和 `arm-linux-musleabi-strip` 是否可执行。

默认安装目录：

```text
$HOME/.local/workcard-toolchain/gcc-20250305-arm-v01c02-linux-musleabi/arm-v01c02-linux-musleabi-gcc
```

该目录位于 Ubuntu/WSL 自身 Linux 文件系统，不需要 `sudo`。不要把工具链手工解压到 `/mnt/c`、`/mnt/d` 等 Windows 盘符目录。

固定工具链版本：

```text
GCC 10.3.0
GNU Binutils 2.41
musl 1.2.3
Linux 5.10 目标头文件
ARM EABI5 soft-float
```

## 6. 编译 camera_demo 示例

首次编译前先完成第 5 节工具链安装。然后回到 SDK 根目录执行：

```bash
cd ../..
cmake -S examples -B build/camera_demo \
    -DCMAKE_TOOLCHAIN_FILE=docs/开发环境/cmake/arm-linux-musleabi-toolchain.cmake
cmake --build build/camera_demo
```

输出文件：

```text
build/camera_demo/camera_demo
```

## 7. 编译 camera_web_demo 示例

在 SDK 根目录执行：

```bash
cmake -S examples/camera_web_demo -B build/camera_web_demo \
    -DCMAKE_TOOLCHAIN_FILE=docs/开发环境/cmake/arm-linux-musleabi-toolchain.cmake \
    -DEHAL_CAMERA_SDK_DIR="$PWD"
cmake --build build/camera_web_demo
```

输出文件：

```text
build/camera_web_demo/camera_web_demo
```

该示例源码使用 `openssl/sha.h` 计算 WebSocket 握手摘要，CMake 已从 `docs/开发环境/runtime/include` 和 `docs/开发环境/runtime/lib` 读取对应 OpenSSL 头文件与库。

## 8. 企业统一工具链目录

企业已经把同一版本工具链安装到统一 Linux 路径时，设置 `WORKCARD_TOOLCHAIN_ROOT`：

```bash
export WORKCARD_TOOLCHAIN_ROOT=/企业实际路径/arm-v01c02-linux-musleabi-gcc
cmake -S examples -B build/camera_demo \
    -DCMAKE_TOOLCHAIN_FILE=docs/开发环境/cmake/arm-linux-musleabi-toolchain.cmake
cmake --build build/camera_demo
```

未设置 `WORKCARD_TOOLCHAIN_ROOT` 时，CMake 使用第 5 节默认安装目录。

## 9. 客户应用编译参数

客户应用包含 SDK 头文件并链接 SDK 动态库：

```c
#include "ehal_camera.h"
```

单文件应用编译命令示例：

```bash
TOOLCHAIN_ROOT="$HOME/.local/workcard-toolchain/gcc-20250305-arm-v01c02-linux-musleabi/arm-v01c02-linux-musleabi-gcc"

"$TOOLCHAIN_ROOT/bin/arm-linux-musleabi-gcc" \
    -std=c11 -O2 -Wall -Wextra \
    -I"$PWD/include" \
    application.c \
    -L"$PWD/lib" \
    -lehal_camera -lpthread -ldl -lm \
    -o application
```

## 10. 架构检查

编译完成后执行：

```bash
file build/camera_demo/camera_demo
readelf -h build/camera_demo/camera_demo
readelf -d build/camera_demo/camera_demo
```

正确结果包含：

```text
ELF 32-bit
ARM
EABI5
interpreter /lib/ld-musl-arm.so.1
```

当前固定固件只部署 ARM EABI5 musl 产物。x86_64、AArch64、glibc、hard-float 产物不部署到目标板。

## 11. 板端运行资源

应用部署到目标板时，运行目录包含以下文件：

```text
bin/<客户应用>
lib/libehal_camera.so
lib/libhal.so
lib/libsns_sc2356.so
lib/libcrypto.so
lib/libcrypto.so.1.1
lib/libssl.so
lib/libssl.so.1.1
configs/hal_default.json
configs/hal.json
configs/hal_sc2356.json
configs/sc2356.json
font/hzk16
```

运行前设置动态库路径：

```bash
export LD_LIBRARY_PATH=/客户部署目录/lib:$LD_LIBRARY_PATH
```

`camera_web_demo` 运行示例：

```bash
cd /客户部署目录
./fix_board_sensor_sc2356.sh
reboot

cd /客户部署目录
./run_camera_web_demo.sh
```

`fix_board_sensor_sc2356.sh` 会将板端 `/etc/init.d/S90autorun` 中的
`/root/insmod.sh <sensor>` 修改为 `/root/insmod.sh sc2356`。重刷 rootfs 或固件后
需要再执行一次，并重启板端让媒体模块按 sc2356 配置重新加载。

`run_camera_web_demo.sh` 会设置 `./lib` 和板端原生运行库路径：
`/app/lib/lib-hal:/app/lib/lib-chip:/app/lib/lib-strms:/app/lib/lib-thrid:/app/lib`，
避免 `libehal_camera.so` 运行时缺少 MPP/BSP/third-party 库。

浏览器访问：

```text
http://<设备IP>:8080/
```

## 12. 编码要求

- 源码、配置和文档统一使用 UTF-8。
- Linux 脚本使用 LF 换行。
- 配置文件不使用 BOM。
- 客户 API 字符串按 UTF-8 处理。
