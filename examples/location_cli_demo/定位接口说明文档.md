# Air780EGP CH390D 路由器 - 定位接口说明文档

## 概述

本项目通过CH390D网口为主控提供网络服务的同时，提供HTTP接口供主控获取模块的定位信息。定位信息包括：
- **GNSS定位**：GPS/北斗/GLONASS/Galileo等卫星定位，精度高（米级）
- **LBS定位**：4G基站定位，精度中等（百米到公里级）

---

## 接口地址

```
GET http://192.168.5.1:8080/location
```

- **协议**：HTTP/1.1
- **方法**：GET
- **IP地址**：192.168.5.1（CH390D局域网网关地址）
- **端口**：8080
- **路径**：/location

---

## 返回数据格式

### 成功响应

**HTTP状态码**：200 OK

**Content-Type**：application/json; charset=utf-8

**响应体示例**：

```json
{
  "gnss": {
    "valid": true,
    "lat": 30.2741520,
    "lng": 120.1551650,
    "speed": 0.125,
    "course": 180.5,
    "altitude": 25.5,
    "time": "2026-10-05 08:30:15 UTC"
  },
  "lbs": {
    "valid": true,
    "lat": 30.2740000,
    "lng": 120.1550000,
    "radius": 500,
    "time": "2026-10-05 16:30:10"
  },
  "timestamp": 1728118215
}
```

### 字段说明

#### gnss 对象（GNSS卫星定位）

| 字段 | 类型 | 说明 |
|------|------|------|
| valid | boolean | 是否有效定位（true=已定位，false=未定位） |
| lat | number | 纬度，十进制度，北纬为正，南纬为负 |
| lng | number | 经度，十进制度，东经为正，西经为负 |
| speed | number | 速度，单位：节（1节≈1.852公里/小时） |
| course | number | 航向角，单位：度（0-360，正北为0） |
| altitude | number | 海拔高度，单位：米 |
| time | string | UTC时间，格式："YYYY-MM-DD HH:MM:SS UTC" |

#### lbs 对象（4G基站定位）

| 字段 | 类型 | 说明 |
|------|------|------|
| valid | boolean | 是否有效定位（true=定位成功，false=定位失败） |
| lat | number | 纬度，十进制度，北纬为正，南纬为负 |
| lng | number | 经度，十进制度，东经为正，西经为负 |
| radius | number | 定位精度半径，单位：米（表示误差范围） |
| time | string | 本地时间，格式："YYYY-MM-DD HH:MM:SS" |

#### 根对象

| 字段 | 类型 | 说明 |
|------|------|------|
| timestamp | number | Unix时间戳（秒） |

### 错误响应

**HTTP状态码**：404 Not Found

**响应体示例**：

```json
{
  "error": "Not Found",
  "message": "接口路径错误，请使用 GET /location"
}
```

## 使用示例

### 1. curl 命令

```bash
curl http://192.168.5.1:8080/location
```

### 2. wget 命令

```bash
wget -O - http://192.168.5.1:8080/location
```

### 3. Python 示例

```python
import requests
import json

# 请求定位数据
response = requests.get('http://192.168.5.1:8080/location', timeout=5)

if response.status_code == 200:
    data = response.json()
    
    # GNSS定位
    if data['gnss']['valid']:
        print(f"GNSS定位: 纬度={data['gnss']['lat']}, 经度={data['gnss']['lng']}")
        print(f"海拔={data['gnss']['altitude']}米, 速度={data['gnss']['speed']}节")
    else:
        print("GNSS未定位")
    
    # LBS定位
    if data['lbs']['valid']:
        print(f"LBS定位: 纬度={data['lbs']['lat']}, 经度={data['lbs']['lng']}")
        print(f"精度半径={data['lbs']['radius']}米")
    else:
        print("LBS定位失败")
else:
    print(f"请求失败: {response.status_code}")
```

```c

```

## 工作原理

### 1. GNSS定位服务（gps_service.lua）

- 使用Air780EGP内置GNSS模块
- 支持GPS/北斗/GLONASS/Galileo/QZSS多系统
- 定位成功后实时更新位置信息
- 每10秒输出一次定位状态到日志

**特点**：
- ✅ 精度高（米级）
- ✅ 实时更新
- ❌ 需要搜星（首次定位需要几分钟）
- ❌ 室内无信号

### 2. LBS基站定位服务（lbs_service.lua）

- 使用4G网络基站信息（MCC/MNC/LAC/CI）
- 调用合宙云LBS定位API转换为经纬度
- 每60秒自动更新一次
- 4G网络就绪后自动启动

**特点**：
- ✅ 室内可用
- ✅ 快速定位（无需搜星）
- ❌ 精度低（几百米到几公里）
- ❌ 需要4G网络

### 3. HTTP接口服务（location_api_service.lua）

- 创建TCP Socket服务器监听8080端口
- 解析HTTP GET请求并返回JSON数据
- 支持多客户端并发访问
- 支持跨域访问（CORS）

---

## 更新频率

| 定位类型 | 更新频率 | 说明 |
|---------|---------|------|
| GNSS | 实时（1Hz） | 定位成功后每秒更新一次 |
| LBS | 60秒 | 每60秒请求一次基站定位API |
| HTTP接口 | 实时查询 | 返回当前最新的缓存数据 |

---

## 注意事项

### 1. 网络依赖

- HTTP服务和LBS定位都需要4G网络就绪
- 如果4G网络未连接，HTTP服务不会启动
- GNSS定位不依赖4G网络，可独立运行

### 2. 定位时间

- **GNSS首次定位**：室外空旷环境下通常需要30秒到3分钟
- **GNSS热启动**：已有星历时通常10-30秒
- **LBS定位**：通常1-2秒内完成

### 3. 定位精度

| 定位方式 | 典型精度 | 使用场景 |
|---------|---------|---------|
| GNSS | 2-10米 | 室外导航、轨迹记录 |
| LBS | 100-5000米 | 室内定位、粗略位置 |

### 4. 数据有效性判断

使用接口时务必检查 `valid` 字段：

```python
# 正确的使用方式
if data['gnss']['valid']:
    # 使用GNSS数据
    lat = data['gnss']['lat']
    lng = data['gnss']['lng']
else:
    # GNSS未定位，使用LBS数据
    if data['lbs']['valid']:
        lat = data['lbs']['lat']
        lng = data['lbs']['lng']
    else:
        # 两种定位都失败
        print("无可用定位数据")
```

### 5. 超时设置

建议设置HTTP请求超时时间为5-10秒，避免长时间等待：

```bash
curl --max-time 5 http://192.168.5.1:8080/location
```

## 故障排查

### 问题1：无法访问HTTP接口

**可能原因**：
1. 4G网络未连接
2. 主控网络配置错误
3. 防火墙阻止

**排查步骤**：
1. 检查主控IP地址是否在 192.168.5.0/24 网段
2. ping 192.168.5.1 检查网络连通性
3. 查看模块日志确认HTTP服务是否启动

### 问题2：GNSS一直未定位（valid=false）

**可能原因**：
1. 天线未连接或损坏
2. 室内环境无卫星信号
3. 遮挡严重

**解决方法**：
1. 检查GNSS天线连接
2. 移到室外空旷环境测试
3. 等待更长时间（首次定位可能需要3-5分钟）

### 问题3：LBS定位失败（valid=false）

**可能原因**：
1. 4G网络未注册到基站
2. SIM卡无数据流量
3. LBS API服务异常

**解决方法**：
1. 检查4G网络状态
2. 确认SIM卡流量正常
3. 查看模块日志中的LBS请求错误信息

## 附录：坐标系统说明

本接口返回的经纬度坐标为 **WGS84 坐标系**（国际标准）。

如需在中国地图上使用，可能需要转换：

| 坐标系 | 说明 | 使用场景 |
|-------|------|---------|
| WGS84 | 国际标准，GPS原始坐标 | 本接口返回的坐标 |
| GCJ02 | 国测局坐标（火星坐标） | 高德地图、腾讯地图 |
| BD09 | 百度坐标系 | 百度地图 |

**坐标转换**：可使用在线工具或坐标转换库进行转换。
