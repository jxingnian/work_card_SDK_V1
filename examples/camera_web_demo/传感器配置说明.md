# 传感器配置说明文档

## 问题背景

本项目使用的硬件传感器是 **SC2356**，但固件层面必须使用 **FPX1002** 驱动（驱动ID: 1002）。

这是因为：
- **物理硬件**: SC2356 传感器
- **固件驱动**: FPX1002 (通过 `/root/insmod.sh fpx1002` 加载)
- **驱动关系**: FPX1002 是为 SC2356 硬件设计的驱动，只是驱动ID不同

## 核心概念理解

### 1. 传感器驱动ID vs 传感器名称

- **驱动ID**: ISP层识别的数字标识（如 1002、2356）
- **传感器名称**: 配置文件和代码中使用的字符串标识（如 "sc2356"、"fpx1002"）
- **传感器库**: 实际的驱动实现（如 `libsns_fpx1002.so`、`libsns_sc2356.so`）

### 2. 三层映射关系

```
配置文件 (hal.json)
    ↓
    sensor.name = "sc2356"
    ↓
HAL层 (libhal.so)
    ↓
    根据传感器名称选择对应的驱动对象
    ↓
传感器驱动库 (libsns_fpx1002.so)
    ↓
    实际与ISP通信的驱动代码
    ↓
ISP层
    ↓
    期望的驱动ID = 1002 (FPX1002_ID)
```

## 问题原因分析

### 错误日志解读

```
ISP[0] Registered sensor is 2356, present sensor is 1002
```

- **"Registered sensor is 2356"**: HAL层注册了ID为2356的传感器驱动（libsns_sc2356.so）
- **"present sensor is 1002"**: 固件层实际加载的是ID为1002的驱动（通过 `/root/insmod.sh fpx1002`）
- **结果**: 驱动ID不匹配，导致ISP初始化失败

### 根本原因

`CMakeLists.txt` 中链接了错误的传感器库：

```cmake
# 错误的配置
sns_sc2356    # 链接了 libsns_sc2356.so (驱动ID: 2356)

# 正确的配置
sns_fpx1002   # 链接了 libsns_fpx1002.so (驱动ID: 1002)
```

## 解决方案

### 1. 修改 CMakeLists.txt

修改根目录的 `CMakeLists.txt` 文件，将所有 `sns_sc2356` 替换为 `sns_fpx1002`：

**位置1**: 第213行（CHIP_LINK_LIBS）
```cmake
set(CHIP_LINK_LIBS
    ...
    securec
    sns_fpx1002    # 修改：原来是 sns_sc2356
    ss_mpi_aibnr
    ...
)
```

**位置2**: 第269行（EHAL_CAMERA_CHIP_LINK_LIBS）
```cmake
set(EHAL_CAMERA_CHIP_LINK_LIBS
    ...
    securec
    sns_fpx1002    # 修改：原来是 sns_sc2356
    ss_mpi_aibnr
    ...
)
```

### 2. 重新编译

```bash
# 清理旧的编译文件
rm -rf build/

# 重新编译
mkdir build && cd build
cmake ..
make -j4

# 同步SDK
make sync_sdk
```

### 3. 完整部署到板端

**重要**: 必须完整部署，不能增量部署

```bash
# 1. 清理板端旧包
ssh xingnian@<板端IP>
cd /home/xingnian
rm -rf camera_web_demo_rtsp/

# 2. 上传新包
scp -r work_card_SDK_V1/build/camera_web_demo xingnian@<板端IP>:/home/xingnian/camera_web_demo_rtsp/

# 3. 板端测试
cd /home/xingnian/camera_web_demo_rtsp
./bin/camera_web_demo --port 8080 --web-root web --default configs/hal_default.json --runtime configs/hal.json
```

## 配置文件说明

### hal.json

```json
{
    "platform": "hi3516cv610",
    "board": "hongou_lite",
    "chip_id": 3516610,
    "sensor": {
        "name": "sc2356",           // 传感器名称（保持不变）
        "config": "sc2356.json"     // 传感器配置文件（保持不变）
    }
}
```

**注意**: `sensor.name` 保持为 "sc2356" 不变，因为：
1. 这个名称用于选择传感器配置文件（sc2356.json）
2. 实际的驱动选择由编译时链接的库决定（CMakeLists.txt中的设置）

### sc2356.json

包含传感器的具体参数配置：
- VI (Video Input) 参数
- VPSS (Video Process Sub-System) 参数
- VENC (Video Encode) 参数
- Pipeline 配置

## 重要注意事项

### ⚠️ 严格禁止修改

根据 `开发提示词.md` 第8条：

```
/etc/init.d/S90autorun.bak保持/root/insmod.sh fpx1002不要给我动、严格执行！无论任何情况都不能碰
```

**永远不要修改 `/root/insmod.sh fpx1002`**，这是固件层的驱动加载脚本，必须保持不变。

### 🔍 故障排查

如果遇到类似错误：

```
ISP[0] Registered sensor is XXXX, present sensor is YYYY
```

**排查步骤**:

1. **检查编译链接的传感器库**
   ```bash
   ldd bin/camera_web_demo | grep sns
   ```
   应该看到 `libsns_fpx1002.so`

2. **检查板端加载的驱动**
   ```bash
   cat /etc/init.d/S90autorun.bak | grep insmod
   ```
   应该看到 `/root/insmod.sh fpx1002`

3. **检查配置文件**
   ```bash
   cat configs/hal.json
   ```
   确认 sensor.name 和 sensor.config 正确

4. **检查库文件是否存在**
   ```bash
   ls -la lib/ | grep sns
   ```
   确认 `libsns_fpx1002.so` 存在

## 为什么厂家demo能运行

厂家的 `sample_board` demo能正常运行是因为：

1. **没有硬编码校验**: 厂家demo不强制要求特定的传感器名称
2. **灵活的传感器选择**: 通过配置文件和编译选项灵活选择传感器驱动
3. **正确的编译配置**: 厂家的编译配置链接了正确的传感器库

我们的demo之前失败是因为：

1. **SDK层硬编码**: `ehal_camera.cpp` 第748行强制只允许 "sc2356"
2. **编译链接错误**: CMakeLists.txt链接了 `libsns_sc2356.so` 而不是 `libsns_fpx1002.so`
3. **驱动ID不匹配**: sc2356驱动ID是2356，但固件需要1002

### 可用的传感器库

**当前项目**: 必须使用 `libsns_fpx1002.so`
